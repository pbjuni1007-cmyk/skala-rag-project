# 기업 IT 문서 검토 환경의 검증 계획

## 확인할 질문

기업 문서 검토에서는 메모리 절감만으로 도입 가치를 판단하기 어렵다. 긴 문서에서 요구사항을 빠뜨리거나 근거 조항을 잘못 연결하면 검토자가 원문을 다시 확인해야 한다. 따라서 문서 검토 품질을 먼저 측정하고, 그 품질을 유지하는 범위에서 KIVI와 InfiniGen의 자원·응답 시간 차이를 비교한다.

현재 서비스는 두 기술을 평가하는 에이전트이며, 두 KV 구현을 탑재한 추론 서버는 아니다. 아래 두 실험은 서로 다른 질문에 답한다. API 기반 에이전트의 실행 시간으로 KV 구현의 성능을 대신 평가하지 않는다.

## 실험 A: 문서 검토 품질

공개 사용이 가능한 RFP·계약·사업 문서에서 최대 3개, 합계 60페이지 이내의 원문을 확보한다. 출처·버전·다운로드 날짜·파일 해시·물리 페이지를 고정한다. 기존 논문 검색 데이터는 그대로 유지하고 별도 실험 자료로 관리한다. 실제 기업 내부 문서는 사용 권한과 비식별 처리가 확보된 경우에만 후속 자료로 사용한다.

| 항목 | 고정할 내용 |
| --- | --- |
| 검토 과업 | 요구사항 추출, 계약 조건 찾기, 문서 간 불일치 확인, 근거 없는 질문에 대한 미확인 응답 |
| 질문 구성 | 선택용 8문항과 미사용 최종 검증용 8문항. 각 과업을 양쪽에 2문항씩 배치 |
| 정답 작성 | 두 검토자가 답과 필수 조건·근거 페이지를 독립 작성하고 불일치를 조정. 답이 없는 질문은 정답을 '미확인'으로 지정 |
| 비교 조건 | 현재 운영 검색 설정과 변경 후보를 같은 문서·질문·생성 모델·추론 수준·입력 및 출력 한도에서 비교 |
| 반복 | 검색 평가는 고정 자료로 재현. 생성 평가는 질문당 3회 반복하며 매회 결과와 사용량을 보존 |
| 검토 방식 | 검토자는 설정 이름을 가린 결과를 평가. 변경 후보는 선택용 질문으로만 결정하고 최종 검증은 선정 후 수행 |

정확한 조항을 찾았더라도 중요한 예외나 적용 조건을 빠뜨리면 완전 정답으로 처리하지 않는다. 요구사항 회수율은 정답에 등록한 필수 요구사항 중 찾아낸 비율, 근거 연결 정확도는 제시한 근거 중 실제 주장을 뒷받침하는 비율로 계산한다. 답이 없는 질문에서는 근거를 만들어 답한 횟수를 별도로 센다. 응답 시간은 전체 소요 시간과 모델 호출 시간을 구분하고, 원시 측정값·중앙값·범위를 함께 남긴다. 이 표본의 p95는 탐색 값으로만 제시한다.

후보의 통과 조건은 필수 조항 누락과 근거 없는 확정 답변이 기준보다 늘지 않고, 요구사항 회수율과 근거 연결 정확도가 기준보다 낮아지지 않는 것이다. 최종 검증에서 성능이 떨어지면 기준 설정을 유지한다. 동일 검증 질문을 보며 다시 튜닝할 경우 해당 질문은 회귀용으로 전환하고 새 미사용 검증 질문을 준비한다. 16문항은 작은 사전 검증이며 실제 문서 전체에 대한 성능 보장을 뜻하지 않는다.

## 실험 B: KV 구현의 품질·자원 비교

공통으로 실행 가능한 모델·토크나이저·정밀도·GPU/CPU·메모리·소프트웨어 버전을 먼저 고정한다. 동일 모델의 기준 KV 구현, KIVI, InfiniGen을 같은 문서와 질문으로 실행한다. 구현 간 공통 지원 환경을 확보하지 못하면 수치를 직접 순위화하지 않고 호환성 제약을 기록한다.

문맥 길이는 공통 지원 한도 안에서 2K·4K·8K, 동시 요청은 1·2·4를 후보 조건으로 둔다. 지원하지 않는 조합은 결과를 만들지 않고 제외 사유를 남긴다. 검색 후 모델에 전달하는 입력은 동일하게 고정하며, 출력 길이·디코딩 설정·워밍업 조건도 맞춘다. 각 조합에서 워밍업 후 5회 측정하고 실행 순서를 교차한다.

| 측정 대상 | 기록 방식 |
| --- | --- |
| 문서 검토 품질 | 실험 A의 정답·근거·누락·미확인 판정으로 평가 |
| 응답 시간 | 첫 토큰 지연, 전체 생성 시간, 출력 토큰당 시간과 처리량 |
| 메모리 | GPU peak allocated/reserved, CPU peak 사용량. 측정 도구와 단위를 함께 기록 |
| 실행 안정성 | OOM·timeout·실패 건수와 해당 조건. 성공한 실행만 남기지 않음 |
| 비교 결과 | 기준 대비 차이를 조건별로 제시. 품질 조건을 통과한 조합에서 자원 이득을 해석 |

품질 통과 조건은 실험 A와 동일하게 적용한다. 자원 이득의 합격 비율은 결과를 보기 전에 운영 요구와 장비에 맞춰 정하며, 정하지 않은 상태에서는 '도입 적합' 판정을 내리지 않는다. 비용은 측정 자원과 처리량에서 산출하고, 외부 API의 토큰 단가를 로컬 KV 구현 비용으로 사용하지 않는다.

## 산출물과 진행 상태

각 실험은 자료 목록, 질문·정답, 실행 조건, 원시 결과, 질문별 비교표와 미해소 사례를 보존한다. 보고서는 실험 A의 검색·검토 품질과 실험 B의 KV 성능을 별도 표로 제시한다.

현재는 실험 명세를 구체화한 상태다. 기존 기업 문서 확보 시도에서 원본 접근 오류가 있었으므로, 사용할 원문과 두 검토자의 정답이 준비돼야 실험 A를 시작할 수 있다. 실험 B는 공통 추론 환경과 장비 확보가 선행돼야 한다. 이번에 측정한 논문 검색·질의 재작성 결과는 이 기업 문서 실험의 결과로 대체하지 않는다.
