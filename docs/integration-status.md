### 목표와 판단 기준

main10의 인용 연결은 존재했지만 고정/변경 변수 혼동, 서로 다른 실험 조건 결합, 잘린 모델명 단정, 추론의 저자 결과 분류가 최종 보고서까지 전파됐다. 최종 Judge는 이를 잡았지만 재조사에서 생성40회를 소진했다. 목표는 모델의 무오류 보장이 아니라 미검증 주장 전파 차단과 제한된 비용 안의 부분 수정이다. KIVI·InfiniGen, 네 관점, LangGraph Supervisor와 하위 역할 간 직접 통신 금지, 동적 conditional edge, 보고서 후 네 기준 평가 및 재작업, 10페이지 이하 출력을 유지한다. 품질 기준 완화나 모델·키·출처 확대는 범위에 없다.

### 선택 구조

1. **근거 묶음:** 기존 원문 청크 ID·해시·페이지·문서 버전을 보존하면서 인접 문맥과 표/그림 설명을 함께 제공한다. 같은 논문의 서로 다른 실험은 별도 experiment ID로 구분한다. 조건 필드마다 원문 위치를 연결하고 고정 변수와 변경 변수를 분리한다. 연결 근거가 없으면 모델·배치·데이터셋을 채우지 않는다. 원문 수정이나 논문별 정답 하드코딩은 하지 않는다.
2. **전파 전 검증:** ResearchAgent가 결과를 Supervisor에 반환하기 전에 구조·인용 검사와 주장 단위 의미 검토를 한다. 검토 항목은 주장 지지, 실험 조건 귀속, 사실/추론 구분이다. 기술 조사뿐 아니라 각 관점이 새로 만든 주장에도 적용한다. 사실 승인, 명시된 추론, 미확인, 수정 필요를 구분하며 실패·누락·타임아웃을 통과로 처리하지 않는다. 마지막 보고서 평가는 유지하며 Writer의 새 종합 주장은 기존 최종 Judge가 검사하며 같은 목적의 별도 호출은 추가하지 않는다.
3. **검증된 근거 재사용:** 원문·조건·검토 결과·revision을 로컬 sidecar artifact로 보존한다. 기존 agent-contract-v1의 wire 필드를 바로 변경하지 않고 내부 adapter에서 관리한다. downstream은 승인된 주장 ID/revision과 그 원문에 의존한다. 요약에서 조건을 되풀이하지 않아도 상세 근거로 추적 가능하게 한다. LLM 의미 판정 역시 비결정적이며 사실 보증으로 표현하지 않는다.
4. **실패 주장만 보완:** claim ID와 문제 유형을 구조화해 전달한다. 근거가 이미 있으면 같은 근거로 해당 주장만 한 번 수정한다. 실제 근거가 부족할 때만 검색한다. 수정 대상 밖 주장 객체는 그대로 보존하고 정해진 직렬화 방식의 해시로 검사한다. 기술 조사 변경 시 실제 의존 claim의 관점만 무효화하고, 의존 관계가 없거나 불명확하면 보수적으로 관련 관점을 다시 검토한다. 보고서·평가는 언제나 변경 후 무효화한다. claim ID는 순서가 아닌 기술·facet 기반 내부 key로 추적한다.
5. **완료 비용 확보:** 코드의 누적 비용·HTTP·생성 상한을 유지한다. 현재 사용량과 남은 Writer·최종 평가·필수 Supervisor 호출·보정 여유를 계산해 추가 조사 전에 완료 가능성을 판단한다. 부족하면 옵션 조사부터 중단하고 필수 부족은 incomplete로 명시한다. 예산 때문에 평가를 생략하거나 자동 통과시키지 않는다. 병렬 호출은 동일한 잠금 아래 예약하며 입력 토큰 계산 요청도 별도로 센다.

대안: 프롬프트만 강화하면 오류를 통제할 경계가 없어 기각한다. 최종 Judge만 강화하면 늦은 복구 비용이 유지돼 기각한다. 모델 교체는 비용·비교 증거가 없으므로 보류한다. 모든 주장마다 LLM 호출을 추가하는 방식 대신 역할별 묶음 검토와 검증 결과 재사용을 선택한다. 의존 그래프와 실험 단위 구조는 복잡도가 늘지만 오류 전파와 반복 생성을 줄이기 위한 범위로 제한한다.

### Architect 검토 반영

- **필수 소비 경계:** 근거 검토 기록은 `(run_id, request_id, result_hash)`에 묶는다. 원문·주장·조건·검토 정책·모델 설정·revision 해시를 포함하고 RunStore의 저장/로드/재개 검증 대상에 등록한다. 후속 관점과 Writer 호출 직전에 확인하며, 누락·변조·오래된 검토·검토 결과 누락이면 해당 모델 호출은 0회다. 단순 로그 저장으로 완료 처리하지 않는다.
- **실험 귀속:** experiment ID를 임의의 사실 승인 표식으로 쓰지 않는다. 주장 안의 측정값·조건 각각에 원문 위치와 실험 귀속 근거를 연결한다. 같은 페이지·청크라도 다른 실험일 수 있다. 모든 실험 필드 작성을 강제하지 않고, 실제 사용한 수치·조건에 대한 연결만 요구한다.
- **상태 구분:** 의미 검토 상태는 Claim.kind와 별개다. 지지되지 않는 주장을 unknown 표시만 붙여 후속 추론의 전제로 전달하지 않는다. 원래 주장은 진단 기록에 남기고 후속 입력에는 확인되지 않은 항목과 필요한 근거만 전달한다. 필수 근거가 빠지면 insufficient로 반환한다. 타당한 조건부 추론은 허용한다.
- **보수적 의존성:** 초기에는 관점 입력으로 제공한 기술 주장 전체를 의존성으로 기록한다. 좁은 연결을 검증한 경우에만 영향 없음으로 재사용한다. 관계 미상은 영향 있음으로 처리하되 재검토와 재생성은 구분한다. 범용 그래프 엔진 대신 역할별 주장 연결표를 사용한다. gaps·conflicts·gap_decisions도 영향을 받는 파생 결과로 무효화한다.
- **수정 식별자:** 내부 key는 `(관점, 기술, facet)`이며 보고서의 순번 claim ID와 대응표를 보고서 해시에 묶는다. 이전 보고서의 Judge 지적이 새 순번에 잘못 적용되지 않게 한다. 명시된 대상 밖 주장 객체를 그대로 보존하며 동일한 직렬화 해시로 확인한다. 기존 근거로 해결되는 수정 경로의 검색 호출은 0회여야 한다.
- **동작 계약:** JSON 필드 v1을 보존하더라도 선택적 무효화는 현재 공통 계약의 변경이다. 구현 시 docs/agent-contract.md의 무효화 규칙·예시와 내부 정책 버전·재개 fingerprint를 함께 갱신한다. 이전 실행의 재개로 새 동작을 적용하지 않는다.
- **비용 우선:** 호출 계획과 완료 여유 검증을 P0로 앞당긴다. 의미 검토를 붙이고 나중에 비용을 맞추지 않는다. 같은 모델의 의미 판단 오판 가능성은 남으며 fake 테스트는 이 정확도를 증명하지 않는다.

Critic은 차단 사항 없이 진행 가능으로 판단했다. 수정 대상 밖 객체의 보존 기준을 직렬화 해시로 통일하고, P0의 모의 호출 검증과 P3의 실제 연결 경로 검증을 구분하라는 의견을 반영했다.

### 호출 계획의 기준선

main10 저장 장부를 재집계하면 첫 Judge까지 25회, 재작업에 15회다. 첫 25회에는 보정 5회와 공백 검토 5회가 포함된다. 이 경로에서 보정을 제외한 기준선은 20회다. 역할별 검토를 기술별2회+관점별3회 추가하면 **정상 시나리오 25회**, 전파 전에 한 주장 수정과 재검토 각1회를 더하면 **27회**를 설계 기준으로 삼는다. 이는 공백 배치5개인 해당 입력의 조건부 호출표이며 새 응답의 예상 성공률이나 실제 비용 예측은 아니다.

생성40회·HTTP100회 한도를 기준으로, 위 정상 경로는 입력 계산을 생성당1회로 가정할 때 HTTP50회, 국소 수정은54회다. 구현에서는 입력 초과 사전검사·분할·보정도 각각 계산하고 이 가정을 실제 fake transport 로그와 대조한다. Writer의 공백 검토는 `ceil(gap_count/5)`회이므로 단순히 Writer1회로 예약하지 않는다. 보정 분할이 기존 최대8회까지 늘면 이 기준선이 깨지므로 별도의 전역 repair allowance를 두고 분할 전에 남은 전체 호출/비용을 확인한다.

**P0 종료 기준:** 새 검토 경로를 연결하기 전 모의 transport로 정상·초기 국소 수정·최종 평가 후 한 관점 수정·근거 부족·병렬 경합별 호출표를 실행 로그로 확정한다. generation과 모든 HTTP를 별도로 세고, 현재 단가/환율/호출별 토큰 상한으로 계산한 비용 예약이 남은 승인 한도보다 크면 추가 요청 전에 중단한다. 금액은 테스트 설정별 원 단위로 기록한다. 완료 여유는 실제 남은 gap 배치·최종 Judge·필수 Supervisor와 허용 보정 횟수로 계산한다. 예산이 모자라면 완성 보장을 주장하지 않는다. 새로운 상한 또는 유료 실행 승인을 만들지 않는다.

### 실행 단계와 종료 조건

- **P0 기록·재현·호출 계획:** 위 호출표와 완료 여유 산식을 먼저 확정한다. README에 관찰/원인/개선 방향을 구분해 추가한다. main10의 다섯 유형을 원문과 함께 고정된 로컬 회귀 fixture로 만든다. 실패 사례뿐 아니라 타당한 조건부 추론과 상세 조건 참조도 포함한다. 코드 기반 결과와 LLM 판정 결과를 구분한다.
- **P1 근거 구조와 소비 경계:** 위 sidecar 저장/로드/재개/소비 차단부터 연결한다. rag/context.py·schemas/evidence 주변에 내부 실험 근거 묶음과 claim dependency/revision을 도입한다. 문맥이 잘렸거나 서로 다른 실험이면 연결되지 않음을 확인한다. 크기 상한과 원문 해시를 검증한다.
- **P2 전파 검증·부분 수정:** researchers 경계에 batch 의미 검토와 제한된 수정 경로를 연결한다. Supervisor는 검증된 결과만 충분성 판단에 사용한다. 통과/미확인/불충분/오류 경로와 잘못된 ID·누락 결과를 모두 검증한다. Writer와 최종 Judge의 역할을 유지한다.
- **P3 의존성·예산:** claim별 대상 수정, 영향 범위만 재검토, 완료 호출 여유를 통합한다. 정상·국소 수정·근거 부족·예산 부족 경로의 모든 generation/HTTP 호출을 계산한다. 정상 및 제한된 국소 수정 경로는 40회/100회 이내 완료하도록 검증한다. 그 밖의 경로는 추가 HTTP 전에 유한 종료를 증명한다.
- **P4 통합 검증·정리:** 네트워크를 차단한 실제 노드 연결 검사, main10 재생, 회귀 검사, 독립 요구사항 검토, ai-deslop을 수행한다. 구조도·계약 설명·README를 구현과 일치시킨다. PDF 테스트는 10페이지 상한과 필수 목차·출처 보존을 확인한다.
- **P5 실제 실행:** 무료 검증과 별도로 모델의 의미 판정 정확도 및 최종 자동 PDF 성공 여부를 확인한다. 새 코드에서의 유료 1회 실행은 별도 사용자 승인이 필요하다. 이전 승인은 소진됐다. 새 캡처와 기존 제출물 교체는 이번 계획에서 자동 수행하지 않는다.

### 수용 기준·복구

미검증 기술 주장이 관점 입력에 들어가지 않고, 관점의 새 미검증 주장이 Writer에 들어가지 않아야 한다. main10 실패 유형에 대한 필드 검증·차단·국소 수정 경로를 재현한다. 근거 부족과 해석 오류를 구분하며, 없는 조건은 만들어 채우지 않는다. 불필요한 재조사와 영향을 받지 않은 관점 재생성을 호출 로그로 확인한다. 정상/보완/불충분 세 경로에서 Supervisor의 상태 기반 분기가 유지된다. 최종 네 기준 통과와 현재 보고서 일치 없이 Publisher가 실행되지 않는다. 실제 LLM 사실 정확도 개선과 자동 PDF 성공은 오프라인 fake 응답만으로 완료 판정하지 않는다.

기존 실행·승인·예산 장부는 변경하지 않는다. 새 내부 artifact version과 코드 fingerprint로 이전 실행 재개를 거부한다. 구현은 단계별 커밋으로 되돌릴 수 있게 하고 기존 원본·제출물은 보존한다. GitHub 문서 반영은 사용자 요청 범위이며 구조 변경의 main 병합과 추가 유료 호출은 별도 승인 지점이다. 계획 검토는 architect → main 반영 → critic 순서다.
