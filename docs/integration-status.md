main-06의 Judge 요청 형식은 수정했고 입력 계산 요청에서 HTTP 200을 확인했다. 이후 사용자 승인에 따라 main-07 한 번에 한해 입력 40,000토큰, 전체 요청 100회, 생성 40회, 추가 비용 1,000원 상한을 적용했다. 과거의 4회 확대안은 활성화하지 않았다.

main-07은 전체 요청 31회(입력 계산 16회·생성 15회)를 사용했다. 비용 장부 증가분은 **약 91.40원**이며 실제 청구서 금액은 아니다. [실패 원인과 수정 검증](main07-citation-recovery.md)을 기록했다. 최초 저장 응답의 6개 주장과 실제 입력 청크 38개가 추가 API 없이 인용 검사를 통과했다. 원본 실행은 계속 `incomplete`이며 새 실제 실행의 성공으로 표시하지 않는다.

## 제출물과 다음 단계

1차 ZIP은 17:48에 제작했다. 7페이지 보고서와 실제 main-02 추적 화면 3개를 포함한다. 기존 분석과 부분 결과의 편집본임을 명시했고, 자동 생성·평가 통과 최종본으로 표시하지 않았다. 원본 ZIP과 실패 기록은 그대로 보존했다.

현재 남은 단계는 다음과 같다.

1. 추가 실행 여부를 사용자와 결정한다. 개인 키의 추가 사용은 자동 진행하지 않는다.
2. 실행을 승인하면 현재 코드로 실제 평가·필요한 수정·발행을 확인한다. 실패 시 추가 실행으로 자동 교체하지 않는다.
3. 새 보고서의 사실·수치·조건·참고문헌을 전수 대조한다. 영향받은 채점과 코드 변경 검증을 갱신한다.
4. 같은 실행의 최종 PDF·추적 화면·ZIP을 대조하고 사람이 검수한다.

추가 실행을 하지 않는 경우에는 현재 코드와 검증 기록, 1차 제출물을 부분 완료 상태로 인계할 수 있다. 최종 자동 보고서와 정상 완료 증거를 확보했다는 주장은 할 수 없다. 원격 main 병합과 실제 과제 제출은 수행하지 않았다.
