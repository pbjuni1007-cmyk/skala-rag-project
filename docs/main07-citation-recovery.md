# main-07 실행 결과와 인용 복구

`agent-20261007-main-07`은 코드 `4e3914a0d81bb8684348821c42337638a0cf553b`에서 실행했다. 기술 조사·도메인·시장성은 결과를 반환했지만 이해관계자 인용 복구에서 중단됐다. 상태는 `incomplete`이며 Writer·Evaluator·Publisher는 실행되지 않았다.

사용자가 승인한 추가 실행 1회를 사용했다. 입력 토큰 계산 16회와 생성 15회로 전체 요청은 31회다. 비용 장부 증가분은 **91.400851원**이다. 장부의 보수적 계산값이며 실제 청구서 금액은 아니다. 실패 이후에는 저장 응답과 원문만 사용해 수정했다.

## 중단 원인

최초 이해관계자 응답에는 인용 위치·표기 오류 세 개가 있었다. PDF의 페이지는 파일의 물리 페이지이며 문자 구간은 추출한 페이지 텍스트의 반열린 구간이다.

| 오류 | 확인한 원문 위치 | 필요한 복구 |
| --- | --- | --- |
| KIVI 잔여 길이를 바꾼 실험 문장이 다른 청크를 가리킴 | `kivi:p7:t750`, 7쪽 `[2423, 2507)` | 청크 위치와 문두 `we` → 원문의 `We` |
| KIVI 그룹 크기 128의 성능 감소 문장이 다른 페이지를 가리킴 | `kivi:p7:t500`과 `t750`, 7쪽의 같은 구간 `[2103, 2175)` | 두 중첩 청크를 한 원문 위치로 식별 |
| InfiniGen victim selection 설명의 문두 대소문자 불일치 | `infinigen:p11:t500`, 11쪽 `[2534, 2616)` | 문두 `we` → 원문의 `We` |

기존 코드는 같은 원문 구간을 포함한 두 청크를 별개 후보로 처리했다. 모델에 보정을 요청하자 인용문 앞에 문장을 덧붙였다. 원문 보존 검사가 이 확장을 거부해 실행이 중단됐다. 앞선 보정 응답에는 다른 실험 문장으로 바꾼 인용도 있었으므로 이를 정상 결과로 채택하지 않았다.

## 수정과 확인 범위

문장 시작의 첫 소문자를 원문의 대문자로 복구하는 경우만 허용한다. 나머지 문자·숫자·구두점은 바꾸지 않는다. 출처·페이지·문자 오프셋·청크 길이가 유효하고, 후보들이 하나의 동일 원문 구간을 가리킬 때만 같은 후보로 처리한다. 위치 정보 누락, 서로 다른 위치, 반복 문구는 모호한 상태로 남긴다. 겹쳐 등장하는 반복 문구도 모두 센다.

[회귀 입력](../tests/fixtures/research/main07_citations.json)과 [테스트](../tests/test_reference_repair.py)는 실제 세 오류, 반복 구간, 다른 출처·페이지·위치, 숫자 변경과 인용 확장 거부를 다룬다. 실제 오류 네 검사와 독립 리뷰가 발견한 겹침 두 검사를 각각 실패 상태에서 확인했다. 수정 후 전체 **848개 검사**가 네트워크 차단 환경에서 통과했다. 저장소 검사 824개와 로컬 실행 승인 보호 검사 24개를 합한 수다.

최초 응답의 6개 주장과 실제 입력 청크 38개를 저장 자료로 다시 검증했다. 주장·조건·한계·공백·상충은 그대로 보존했고 새 API 요청은 0회였다. 이 결과는 **인용 복구 검증**이다. 실제 실행 상태를 바꾸거나 보고서·품질 평가 성공을 증명하지 않는다.
