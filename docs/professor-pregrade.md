# 교수 가이드 기준 독립 사전 채점

서로 다른 세 검토자가 가이드의 일곱 배점을 나누어 코드와 실행 증거를 확인했다. 합계는 **91/100점**이다. 실제 교수 성적이나 최종 제출 승인으로 해석하지 않는다. 실제 평가·발행의 완료 증거와 보고서 내용 보완이 남아 있다.

| 검토자 | 평가 항목 | 점수 | 판단 |
| --- | --- | ---: | --- |
| A | 패턴 적용 정합성 | 20/20 | 상태에 따른 분기·근거 판단·재작업·종료 구현 |
| A | State Schema 설계 | 20/20 | 일곱 설계 항목의 설명과 구현 일치 |

## 점수의 근거와 한계

B는 `agent-20261007-main-02`의 `research → domain → domain 재작업`, main-04의 네 관점 조사 뒤 `research 재작업`을 실제 이벤트와 LangSmith의 동일 요청 ID로 대조했다. 재작업 이후 실패했다는 이유로 이미 확인된 동적 라우팅을 감점하지 않았다. main-06에는 실제 Writer 보고서가 있지만 Evaluator가 실패했고, main-07은 Writer 이전에 중단됐다. 따라서 정상 완료한 결과를 같은 실행의 trace와 함께 재현하는 부분에서 5점을 감점했다.

C는 가이드가 품질 평가 노드의 구현과 반복 경로를 코드로 확인하도록 한 점을 적용했다. 실제 모델 평가가 미완료라는 이유로 구현 자체를 감점하지 않았다. 보고서에서는 KIVI의 고정·변경 변수 혼동, InfiniGen의 실험조건 혼동, 기술 성숙도 과장, 사실·추론 혼동으로 4점을 감점했다. [전수 Reference Check와 수정안](reference-check-main06.md)에 대상 주장과 원문 근거가 있다.

평가 대상 코드와 실증 범위는 다음과 같다.

- 현재 코드: `a6062a9af428ebc54a6c1bc82782c20f7e3aba2d`. B·C가 이 코드에서 평가했다.
- A의 패턴·State 검토: `4e3914a0d81bb8684348821c42337638a0cf553b`. 이후 변경은 인용 복구와 관련 테스트뿐이다. A가 검토한 33개 파일이 현재와 해시까지 같음을 확인해 해당 판단을 재사용했다.
- 전체 848개 오프라인 검사와 새 고정 환경의 152개 검사는 실행 증거를 보조한다. 검사 개수 자체를 점수로 사용하지 않았다.
- 실제 trace는 각 실행 당시 코드의 증거다. 과거 trace를 현재 코드가 정상 완료한 증거로 바꾸지 않았다.
- 1차 제출물은 기존 분석과 부분 결과의 편집본이다. 자동 생성·품질 통과 보고서로 평가하지 않았다.

## 남은 보완

확인된 보고서 오류는 원문·실험조건과 함께 별도 수정안으로 기록했다. 조사 문맥과 Judge 지침을 보완했고, [main-07 인용 오류](main07-citation-recovery.md)는 저장 응답으로 재현해 수정했다. 그러나 이 코드 보완이 새 보고서의 의미 정확성까지 보장하지는 않는다.

정상 완료를 주장하려면 현재 코드의 실제 Writer → Evaluator → 필요한 수정 → Publisher 결과가 필요하다. 그 보고서를 다시 전수 검토하고, 같은 실행의 PDF·trace·ZIP을 검수해야 한다. 추가 유료 실행은 별도 승인이 필요하다.

세 검토자의 원문 판정·검토 파일 해시·검증 기록은 로컬 `outputs/team-integration/professor-final-{a,b,c}-review.md`, 각 `*-receipt.json`과 `*-files.sha256`에 보존했다. 코드 변경자는 세 검토자와 다르며, 검토 중 파일 수정이나 API 호출은 없었다.
