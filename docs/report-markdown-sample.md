# PDF 담당자용 Markdown 계약 샘플

이 파일은 보고서 출력의 제목, 인용 위치, 참고문헌 구조를 보여주는 형식 샘플입니다. 대괄호 안 문구는 값의 위치를 설명하는 자리표시자이며, 조사 결과나 품질 판정을 담지 않습니다. 실제 출력은 `outputs/<실행ID>/report.md`를 사용합니다.

## 고정 구조

1. `# SUMMARY`
2. `# 기술 성숙도`
3. `# 시장성`
4. `# 이해관계자`
5. `# 도메인 적용`
6. `# 관점 간 상충과 한계`
7. `# REFERENCE`

## 형식 샘플

```markdown
# SUMMARY

**[기술명]** [팀 해석] [근거와 적용 조건을 함께 쓴 요약 주장] [1, 물리 p.1]

**대상 기술:** KIVI / InfiniGen
**단일 도메인:** [설정에 기록된 도메인]
**적용 가정:** [설정에 기록된 시나리오]

# 기술 성숙도

## KIVI | [claim-id]

**[주장 종류]** [실험 조건과 한계를 보존한 주장] [1, 물리 p.1]

**조건:** [원문에서 확인한 조건]

**한계:** [판단에 영향을 주는 한계]

# 시장성

| 비교 질문 | KIVI | InfiniGen |
| --- | --- | --- |
| [facet] | [주장, 인용, 검수 링크] | [주장, 인용, 검수 링크] |

# 이해관계자

[문서 검토자, 운영자, 구매 또는 보안 담당자의 효익과 부담을 근거에 연결]

# 도메인 적용

[적합 조건, 위험, 확인할 실험을 근거와 함께 기술]

# 관점 간 상충과 한계

[조건에 따른 비교와 남은 한계를 기술. 무조건적인 우승 또는 추천 표현은 사용하지 않음]

## 남은 근거 공백

[미해결 공백과 검수표 링크]

# REFERENCE

[1] [저자] ([발행일]). **[제목]**. [자료 유형과 버전]. 조회 [날짜].
[원문 URL]
```

## 출력 약속

- 본문 인용은 `[번호, 위치]` 형식이며 번호는 사용된 출처만 대상으로 매깁니다.
- `REFERENCE`의 번호와 본문 번호는 일치하고, 각 항목에 제목, 버전 또는 자료 유형, 조회 날짜, 원문 URL이 들어갑니다.
- 요약은 `SUMMARY` 아래에 두고 1200자 상한을 넘기지 않습니다.
- Markdown과 PDF는 같은 보고서 본문에서 생성됩니다. Judge 통과는 PDF 페이지 검수 통과를 뜻하지 않습니다.
- 실제 페이지 나눔, 글꼴, 표 잘림은 PDF 담당자가 생성된 PDF에서 확인합니다.
