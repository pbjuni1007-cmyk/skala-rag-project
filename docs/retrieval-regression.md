# 검색 설정 회귀와 질의 재작성 검증

현재 운영 설정은 E5-small의 고정 버전, 청크 300토큰·겹침 50, 검색 5개다. 검색 설정을 바꿀 때 기존에 회수하던 원문과 실험 조건이 사라지는지 확인하기 위해 운영 함수로 회귀 검사를 수행한다. 새 모델의 일반화 성능 평가는 별도의 미사용 질문으로 수행한다.

## 실행과 기준 관리

`app.py`는 인덱스 생성 후 `eval/retrieval-baseline.json`과 현재 검색 결과를 비교한다. 모델 버전, 청크, 검색 개수, 문맥 예산, 자료, 질문, 검색 코드와 라이브러리 버전을 식별 정보에 포함한다. 동일한 통과 결과가 있으면 재사용하고, 바뀌면 재평가한다. 유료 생성은 검사가 통과한 뒤에만 시작한다. `--prepare`에도 적용하고 저장 결과만 렌더링하는 `--render`에는 적용하지 않는다.

아래 명령은 내려받은 모델과 원문을 사용하며 네트워크·LLM 호출 없이 실행한다. 기본 모델은 운영 기본값 E5-small이며 다른 운영 모델을 사용하면 `--model`과 필요 시 `--revision`도 명시한다.

```bash
python scripts/revalidate_retrieval.py check \
  --baseline eval/retrieval-baseline.json \
  --output outputs/retrieval-regression.json
```

현재 설정으로 새 측정 후보를 만들려면 `evaluate --output <후보.json>`을 사용한다. `approve-baseline --output <후보.json> --baseline <새_기준.json> --candidate-sha256 <검토한_파일의_SHA256>`은 해당 후보를 명시적으로 기준으로 고정한다. 기존 기준을 덮어쓰지 않는다. 원문이나 질문이 달라져 비교할 수 없는 경우, 성능 하락을 통과시키기 위해 기준을 자동으로 갱신하지 않는다.

영어 질문마다 상위 검색 결과와 운영 문맥의 완전 회수·조건 회수가 기준보다 낮아지지 않아야 한다. 한국어 결과는 진단용으로 함께 기록한다. 평균 상승으로 특정 질문의 하락을 가리지 않는다. 빈 정답, 원문 위치·해시 불일치, 오래되거나 변경된 측정 결과도 확인한다.

## 검색 개수 비교

2026-09-22에 기존 영어 질문 24개를 다시 측정했다. 기존에 노출된 선택·검증 질문을 포함하며, 단일 질문을 입력한 회귀 측정이다. 실제 생성 질의나 네 facet을 묶는 기술 조사 전체의 정확도로 해석하지 않는다.

| k | 상위 검색 완전 회수 | 문맥 구성 후 완전 회수 |
| --- | --- | --- |
| 3 | 16/24 | 20/24 |
| 5 | 20/24 | 21/24 |
| 8 | 21/24 | 22/24 |
| 10 | 21/24 | 22/24 |

k=5의 조건 회수 평균은 검색 결과 87.5%, 운영 문맥 89.58%였다. k=8과 10은 알려진 질문을 더 회수했지만 전체 생성 품질과 비용은 이 실험에서 측정하지 않았다. 운영값을 5로 유지하고 현재 측정치를 회귀 기준으로 삼았다.

[측정 후보](../experiments/retrieval-regression-20260922/candidate.json), [기준](../eval/retrieval-baseline.json), [통합 후 재검증](../experiments/retrieval-regression-20260922/checked.json)에 질문별 결과, 실제 문맥 토큰 수, 소요 시간과 식별 정보가 있다. 처음 측정과 통합 후 재검증은 코드 해시가 다르므로 재측정을 수행했다.

## 질의 재작성의 전후 비교

저장된 기술 조사 기록에서 재검색이 발생한 모든 6건을 수집하고, [전후 질의](../eval/rewrite-pairs.json)를 고정했다. 원래 실행 당시의 성능 비교가 아니라 같은 현재 검색·문맥 설정으로 두 질의를 다시 실행한 통제 비교다. 기준 원문은 기존 조건 진단 질문을 사용했다.

```bash
python scripts/evaluate_rewrite.py \
  --output experiments/rewrite-20260922/results.json
```

| 실행 기록 | 기술 | 재작성 전 완전 회수 | 재작성 후 완전 회수 |
| --- | --- | --- | --- |
| 20260921T100118-6dfbc0 | InfiniGen | 5/10 | 4/10 |
| 20260921T100118-6dfbc0 | KIVI | 5/10 | 5/10 |
| 20260921T100525-27ea3e | InfiniGen | 2/10 | 5/10 |
| 20260921T103300-917c01 | InfiniGen | 2/10 | 5/10 |
| 20260921T103742-b26f39 | InfiniGen | 2/10 | 5/10 |
| 20260922T024141-f6e6db | KIVI | 5/10 | 4/10 |

세 개선 기록은 동일한 질의 쌍이다. 중복을 제외한 네 쌍에서는 개선 1건·유지 1건·악화 2건이었다. 이 작은 관측 표본으로 재작성의 일반적 성공률을 주장하지 않는다. 질의가 바뀌면서 기존 근거가 빠질 수도 있으므로 재검색 후 충분성과 인용을 다시 검사하며, 한 번의 보완 후에도 부족하면 미완료로 종료한다.

[원시 결과](../experiments/rewrite-20260922/results.json)에는 질문별 회수 여부, 신규 문맥 청크, 문맥 토큰과 원본 해시를 보존했다. 모델 답변 정확성·기업 문서 성능·KV 구현 성능은 측정 범위에 포함되지 않는다.
